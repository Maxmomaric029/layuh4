## FILE 1: `misc.cpp` — **CRITICAL & HIGH SEVERITY BUGS**

### BUG 1 (CRITICAL): `NoJumpCoolDown()` writes `bool` to a `float` offset (Lines 805-810)
```cpp
// Line 805-809
if (vars::misc::nojumpcooldown) {
    write<bool>(humanoid + offsets::JumpPower, false);  // BUG!
}
else {
    write<bool>(humanoid + offsets::JumpPower, true);   // BUG!
}
```
**Problem**: This writes a `bool` type to `offsets::JumpPower`, which is a **float** offset (used correctly in `jump_power()` on line 611 as `write<float>(humanoid + offsets::JumpPower, jumpPower)`). Writing a `bool` to a float field corrupts the float value. It should be using a dedicated `JumpCoolDown` offset, not `JumpPower`. Also, the logic is inverted — `nojumpcooldown = true` writes `false` — which sort of makes sense semantically ("no cooldown" = disable cooldown), but using `JumpPower` is wrong.
**Fix**: Use the correct offset for jump cooldown (e.g., `offsets::UseJumpPower` or a dedicated cooldown offset), and write the correct type.

### BUG 2 (CRITICAL): `NoJumpCoolDown()` conflicts with `jump_power()` — both write to same offset simultaneously (Lines 594-619 vs 792-811)
**Problem**: Both functions are called every frame in the overlay loop (lines 168 and 173 of overlay.cpp). If both `vars::misc::jump_power_enabled` and `vars::misc::nojumpcooldown` are true, they fight over `humanoid + offsets::JumpPower` — `jump_power()` writes a float, `NoJumpCoolDown()` writes a bool. The bool write will overwrite the first byte(s) of the float.
**Fix**: Ensure mutual exclusivity or use different offsets.

## FILE 5: `renderer.cpp` — **RESOURCE LEAK**

### BUG 19 (MEDIUM): `draw_text()` creates a new `IDWriteTextFormat` every single call (Lines 87-111)
```cpp
void draw_text(const std::string& text, float x, float y, float size, ...) {
    IDWriteTextFormat* format = nullptr;
    dWriteFactory->CreateTextFormat(..., size, ..., &format); // Allocates every call!
    ...
    format->Release();
}
```
**Problem**: Every call to `draw_text()` creates and destroys a `IDWriteTextFormat` COM object. This is called many times per frame (ESP names, distances, health, etc.). This is extremely slow due to COM allocation overhead. The default `textFormat` created on line 26-34 of `initialize()` is **never used**.
**Fix**: Cache text formats by size, or use the default `textFormat` when size is 16.0f.

### BUG 20 (LOW): `get_text_size()` also creates a new `IDWriteTextFormat` every call (Lines 221-222)
Same issue as above.

### BUG 21 (LOW): wstring includes null terminator causing potential off-by-one (Lines 83-85, 217-219)
```cpp
int len = MultiByteToWideChar(CP_UTF8, 0, text.c_str(), -1, NULL, 0); // Includes null terminator
std::wstring wtext(len, 0); // Allocates len chars + internal null
MultiByteToWideChar(CP_UTF8, 0, text.c_str(), -1, &wtext[0], len); // Writes null into string
```
Then on line 107: `d2dRenderTarget->DrawText(wtext.c_str(), wtext.length() - 1, ...);`
The `- 1` compensates for the embedded null, but the string contains a null character inside it which is messy. Better approach: use `-1` to exclude the null in the initial `MultiByteToWideChar` call, or use `len - 1` for the wstring size.
